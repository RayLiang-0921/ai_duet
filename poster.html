目的
以輕量的馬可夫鏈作為決策核心，建構兩個能即時學習、相互適應的音樂代理，讓它們在鋼琴上進行無限的 Call and Response 對話，並開放人類即時介入合奏。
研究問題
  • 僅用統計轉移機率，能否產出具音樂性的旋律？
  • 兩個代理聆聽彼此，對話是否會收斂或演化？
  • 人類介入後，AI 回應能否自然融入人類音符？
系統目標
  • Agent A：C 大調（穩定和聲）；Agent B：G 混合利底亞調（藍調色彩）
  • Web 版支援 24 種調性，可即時切換不中斷
  • 人類透過鍵盤即時彈奏，下一小節 Agent 自動學習
  • 前端 Piano Roll 視覺化下落式音符動畫
讓 AI 演奏不像「自動播放」，而是有如真正在聆聽的即興樂手。

① 馬可夫鏈核心
記憶體為巢狀字典，儲存「音符 A 後接 B 的次數」，取樣時以次數加權： 
# 聆聽後更新轉移矩陣
self.memory[cur][nxt] += 1  # 累積權重

# 生成：70% 加權抽樣，30% 隨機游走
if cur in self.memory and random() < 0.7:
    next_note = choices(keys, weights=weights)[0]
else:
    idx += choice([-2,-1,0,1,2])
② 和弦骨架引導（80/20）
每小節隨機選取 I/IV/V/VI 級三和弦為骨架；Agent 80% 機率選和弦音確保和諧，20% 選非和弦音增加張力。
③ 鼓聲 + 人類互動
大鼓 step 0,8；軍鼓 step 4,12（4/4 拍）。鍵盤 ASDFGHJK / WETYU，按 Z/X 切八度；彈錯音閃紅燈防呆，後端下一小節納入學習。

結論
主要發現
  • 一階馬可夫鏈 + 音階引導，在多次對話後產生旋律「記憶感」，出現慣用樂句的雛形。
  • 和弦骨架（80% 和弦音 / 20% 非和弦音）有效降低不和諧感，聆聽體驗接近真實即興。
  • 人類插嘴後三方對話自然過渡，無明顯斷裂感；WebSocket 延遲 < 50ms。
未來展望
  • 升級至二/三階馬可夫鏈，捕捉更長樂句連貫性
  • 以 LSTM / Transformer 取代，學習複雜音樂結構
  • 加入情感參數（緊張度、速度斜率）調控演奏情緒
  • 多人 WebSocket，多位人類 + 多 AI 共同即興合奏
  • 整合真實鋼琴 MIDI 輸入，與真實樂手對奏
這場人機音樂對話才剛開始——每個小節都是一次全新的即興。
